# 架构

Personal Agent 是单人、单网关、多设备的本地系统。CLI、Electron 和 Expo 都只通过 `@pa/sdk` 与 `@pa/contracts` 连接 Gateway。应用数据库和 LangGraph 检查点只存在于 Gateway 进程。

## 进程

- Gateway 是唯一执行器。启动时用 SQLite 中的 `executor_lock` 取得 fencing token；活着的其他进程不能再接管。
- 业务状态在 `app.sqlite`。LangGraph `SqliteSaver` 的 `checkpoints.sqlite` 只记录根运行执行到哪一步。两者没有跨库事务。
- 检查点写入前会确认应用库租约仍属于本进程。官方 SqliteSaver 本身不能给外部副作用加栅栏，所以本版本明确只支持单执行器，并在启动时做对账。

## 一次根运行

每条用户消息创建一个根运行。演示模式的标准任务会：

1. 记录模型步。
2. 并行启动两名只读专员，各自只拿到自己的目标和文件名。
3. 专员通过同一套工具账本读取资料。
4. 协调者只根据已落账的专员结果生成草稿，并先发出不入库的预览。
5. 在真正写文件前插入审批并让 LangGraph `interrupt`。
6. 另一个设备批准后，用同一个 `thread_id` 恢复，并只写入一次。

根预算默认 30，统计根运行和专员的全部工具调用，包括失败。预算数字只增不减。审批等待使用单独的 TTL，不计入执行时限。

## 工具账本

稳定的 `logical_key` 在调用前写入。顺序是：意图、必要时审批、原子认领为 `dispatching`、外部动作、结果与事件落库、然后检查点才向前。已经终态的账本记录会在恢复时直接回放，演示写入因此不会对同一个逻辑调用再执行一次。这只覆盖当前账本和本地 `sandbox/notes` 文件，不是对任意外部系统的恰好一次保证。`dispatching` 在进程重启后变成 `outcome_unknown`，系统不会自动重放写入。

## 事件

`events.seq` 是全局自增整数。游标是带 HMAC 的不透明字符串，里面包含 epoch、序号、身份和过期时间。回放按身份过滤，序号空洞是正常的。客户端不得用空洞推断自己丢了事件。快照和水印在同一个读事务里读取。实时连接先订阅总线，再读回放，然后按 `eventId` 去重接上实时流。

预览帧不写事件表，也不推进游标。断开 WebSocket 不会取消运行。
